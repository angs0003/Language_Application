# 0001: Four-tab navigation, no fifth tab

## Context
The first interface had 8 section buttons at the top plus language tabs and settings. Research on mobile navigation and autism-friendly design (bottom tab bars with 3 to 5 items, simple consistent layouts) showed this was too much.

## Decision
A bottom tab bar with exactly 4 tabs: Learn, Practise, Listen, Travel. Settings behind the profile button. New features go inside an existing tab.

## Consequence
Any feature request must name the tab it belongs to. A proposal for a fifth tab needs a new decision file and the owner's approval.
